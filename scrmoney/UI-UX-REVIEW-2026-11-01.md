## Спор: два раунда

### Раунд 1

- UX предлагает поднять прогресс и уменьшить лозунг. Creative возражает против отказа от рукописного характера и против тесной строки «длинный лозунг + кнопка». Компромисс: краткая строка «раздел/дата + цель», рукописный лозунг ниже, размер 26–28 CSS px.
- Creative предлагает сохранить узнаваемый календарь. Frontend предупреждает: снятие line-clamp со всего события даст непредсказуемую высоту. Компромисс: до двух строк названия и отдельная полная сумма; для остальных событий — реальные подробности дня.
- Frontend предлагает сначала убрать конфликт классов. UX поддерживает: сначала вернуть полезную ширину, затем уменьшать отдельные элементы.

### Раунд 2

- UX требует сохранить область добавления цели не меньше 44×44 CSS px. Creative допускает перенос строки и года даты; не требуется удерживать всё на одной строке любой ценой.
- Frontend уточняет: подробности календаря требуют обработчика и клавиатурного доступа, один title недостаточен. Команда не включает фиктивную кнопку в быстрый CSS-патч.
- Все согласны: ручной расход остаётся вторичным; «Обновить остатки» сопровождается «Проверка раз в месяц», без постоянного навязчивого акцента. Разные суммы и даты сначала явно подписываются по периодам и сценариям.

### 6. События календаря

Для готовой замены модели событий в dayStickers() использовать отдельные поля названия и суммы:

```js
function dayStickers(list) {
  if (!list || !list.length) return [];
  const out = [];
  const add = (k, n, sign, value) => out.push({ k, n, amount: sign + gel(value) });
  const need = list.filter(e => e.kind === 'need');
  const goal = list.filter(e => e.kind === 'goal');
  for (const e of list.filter(e => e.kind === 'inc')) add('inc', e.n || 'Доход', '+', e.gel);
  if (need.length > 1) add('need', `Платежи: ${need.length}`, '−', need.reduce((s, e) => s + e.gel, 0));
  else for (const e of need) add('need', e.n || 'Платёж', '−', e.gel);
  for (const e of list.filter(e => e.kind === 'once')) add('once', e.n || 'Разовая трата', '−', e.gel);
  if (goal.length > 1) add('goal', `На цели: ${goal.length}`, '−', goal.reduce((s, e) => s + e.gel, 0));
  else for (const e of goal) add('goal', e.n || 'На цель', '−', e.gel);
  return out;
}
```

В calMonth() заменить генерацию элементов st (старое st.map с x.t) на:

```js
${st.map(x => `<i class="st ${x.k}"><span class="st-name">${esc(x.n)}</span><b class="st-amount num">${esc(x.amount)}</b></i>`).join('')}
```

```css
}

  display: block;
  white-space: nowrap;
  font-weight: 600;
}
```

Этот фрагмент сохраняет все события и не создаёт нового взаимодействия. Высоту строк при нескольких событиях следует проверить. Ограничение «два события + Ещё N» внедрять только вместе с работающими подробностями дня, доступными касанием и с клавиатуры; не терять оставшиеся события и не заменять подробности атрибутом title. На очень длинных суммах допускается перенос валюты отдельным неразрывным фрагментом после проверки ширины.

Внутренние линии календаря сделать 1 px var(--rule), оставить внешнюю границу темнее. Круг текущего дня перенести с .cd .circ на число даты; жёлтое выделение дня сохранить. Это отдельная визуальная правка, не условие сохранения сумм.
